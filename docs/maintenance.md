# РЕГЛАМЕНТ ТЕХНИЧЕСКОГО ОБСЛУЖИВАНИЯ (ТО) ПО «Kubiki»

## 1. Паспортная часть и общие положения

1.1. Назначение документа
Настоящий регламент определяет порядок, периодичность и содержание работ по техническому обслуживанию консольного приложения «Kubiki» (Калькулятор квадратных уравнений). Целью внедрения регламента является минимизация простоев, предотвращение потери пользовательских данных (коэффициентов) и обеспечение стабильной работы программного обеспечения.

1.2. Область применения
Правила распространяются на:
*   Программное обеспечение: консольное приложение на языке Python (файл src/main.py).
*   Файловую систему: папку data (файлы входных данных input.txt, результатов output.txt и резервных копий backup_input.txt).
*   Аппаратное обеспечение: персональный компьютер пользователя (или сервер), на котором запускается интерпретатор Python.

1.3. Роли участников
*   Пользователь: вводит данные, запускает программу, выполняет базовые операции по резервному копированию (через меню программы).
*   Администратор / Разработчик: отвечает за установку обновлений (через Git), проверку целостности файлов программы и восстановление данных в случае критических сбоев.

## 3. Контроль качества и отчетность

3.1. Параметры контроля (метрики для статистики)
Для оценки эффективности ТО и стабильности работы системы используются следующие измеримые параметры:

1. Количество успешных запусков программы (шт./сутки): Считается общее число успешных решений уравнений за день. Позволяет оценить нагрузку на систему.
2. Коэффициент успешных операций (%): Отношение количества успешно обработанных запросов (без ошибок) к общему числу запросов за период. Норматив: не менее 99%.
3. Количество обработанных исключений (шт.): Число зафиксированных ошибок ввода (например, ввод букв вместо цифр) и системных сбоев. Позволяет выявить проблемные зоны интерфейса.
4. Среднее время отклика системы (сек.): Время от момента ввода последнего коэффициента до вывода результата на экран. Норматив: не более 1 секунды.
5. Количество созданных резервных копий (шт./месяц): Показывает регулярность выполнения профилактических работ пользователем.
6. Количество инцидентов восстановления данных (шт./месяц): Сколько раз использовался пункт 4 (восстановление из бэкапа). Если показатель растет — требуется провести внеплановый инструктаж пользователя.
7. Объем занимаемого дискового пространства (КБ): Размер папки data за отчетный период. Контролируется, чтобы файлы с коэффициентами не занимали слишком много места.
